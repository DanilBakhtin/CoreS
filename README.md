Документ описывает назначение плагина, его установку в проект Unreal Engine и основные точки расширения тренажёра. Настройку начинайте с подключения модуля и контента, затем задайте коллизии, классы проекта и параметры курса.

Основа описания — версия Development.43e02f5 от 17.06.2026. Для другой версии сверяйте названия полей, классов и требования к интеграции с исходным кодом.

<a id="section-01"></a>
### Термины

АОС — автоматизированная обучающая система.

РШ — редактор шагов АОС.

<a id="section-02"></a>
## Возможности плагина

- WebSocket-сервер обеспечивает двусторонний обмен: АОС выступает клиентом, тренажёр — сервером.
- Базовые классы содержат логику, которую можно расширять в конкретном тренажёре.
- Интерактивные объекты и компоненты реагируют на действия пользователя и команды АОС.
- Виджеты содержат интерфейс тренажёра и связанную с ним логику.

<a id="section-03"></a>
## Установка и подключение

<a id="section-04"></a>
### 1 Подготовьте файлы плагина

<a id="section-05"></a>
#### Получите исходный проект

Скачайте проект Core Simulator из внутреннего GitLab:

```text
https://onil-git/unreal-engine/coresimulator
```

Рабочую ветку уточните у технического руководителя проекта.

<a id="section-06"></a>
#### Скопируйте плагин и контент

Скопируйте каталог Plugins из проекта coresimulator в корень нового проекта.

![Папка плагина Core Simulator](core-simulator-01-plugin-folder.png)

Из каталога Content исходного проекта скопируйте в Content нового проекта папки Images, Movies и Locales. Images содержит типовые изображения интерфейса и схемы; Movies — видео экрана загрузки; Locales — JSON-файлы локализации и постоянных текстов меню.

![Папки Images, Locales и Movies](core-simulator-02-content-folders.png)

<a id="section-07"></a>
### 2 Включите плагин и модуль

Включите плагин в обозревателе плагинов Unreal Engine и перезапустите проект.

![Включение плагина в Unreal Engine](core-simulator-03-plugin-enable.jpg)

Добавьте модуль Core_Simulator в PrivateDependencyModuleNames.AddRange файла `<ИмяПроекта>.Build.cs`:

```text
PrivateDependencyModuleNames.AddRange(new string[]
{
"Core_Simulator"
});
```

<a id="section-08"></a>
### 3 Настройте коллизии

Для взаимодействия с объектами добавьте в Project Settings → Engine → Collision канал трассировки и профиль коллизии с указанными ниже именами и значениями.

<a id="section-09"></a>
#### Канал трассировки TC_Interact

Создайте Trace Channel со следующими параметрами:

```text
Name: TC_Interact;
Default Response: Ignore.
```

![Настройки канала трассировки TC_Interact](core-simulator-04-trace-channel.jpg)

*Параметры канала TC_Interact.*

<a id="section-10"></a>
#### Профиль InteractObject

Создайте Collision Preset со следующими параметрами:

```text
Name: InteractObject;
CollisionEnabled: Query Only (No Physics Collision);
ObjectType: WorldDynamic;
Description (Опционально): Interact Object Collision;
Collision Responses:
	Trace Type:
		Visibility:	Block;
		Camera:		Ignore;
		TC_Interact:	Block;
	Object Type:
		WorldStatic:	Ignore;
		WorldDynamic:	Block;
		Pawn:		Block;
		PhysicsBody:	Ignore;
		Vehicle:		Ignore;
		Destructible:	Ignore.
```

![Настройки профиля коллизии InteractObject](core-simulator-05-collision-preset.png)

*Параметры профиля InteractObject.*

<a id="section-11"></a>
### 4 Укажите классы и карты проекта

<a id="section-12"></a>
#### Game Mode

В Project Settings → Maps & Modes выберите BP_CS_GameMode в Default GameMode. Можно использовать собственный класс, унаследованный от CS_GameMode: так базовая логика плагина останется доступной.

![Настройки карт и игрового режима проекта](core-simulator-06-maps-and-modes.jpg)

*Выбор Game Mode.*

<a id="section-13"></a>
#### Стартовая карта

В разделе Default Maps задайте Game Default Map = StartMap. Эта карта нужна механизму отслеживания завершения загрузки рабочей карты тренажёра. Для Editor Startup Map выберите StartMap либо рабочую карту тренажёра.

![Настройки карт и игрового режима проекта](core-simulator-06-maps-and-modes.jpg)

*Выбор стартовой карты.*

<a id="section-14"></a>
#### Game Instance

В разделе Game Instance выберите CS_GameInstance или его дочерний класс. Он инициализирует менеджер локализации и предоставляет базовые настройки качества графики (уровни 3 и 5).

![Выбор класса Game Instance](core-simulator-07-game-instance.png)

*Выбор Game Instance.*

<a id="section-15"></a>
## Настройка тренажёра

<a id="section-16"></a>
### Параметры проекта

Откройте раздел Core Simulator Settings в настройках проекта и задайте параметры курса.

![Параметры Core Simulator Settings](core-simulator-08-project-settings.jpg)

- Core Simulator Settings — настройки курса.
- Start Location — служебный идентификатор локации для взаимодействия интерфейса с АОС; обычно его менять не требуется.
- Course Version — версия протокола АОС. Она должна совпадать с версией, указанной для тренажёра в системе данных. В описываемой версии используется значение 3.
- Simulator Params Asset — Data Asset с идентификаторами кнопок HUD, изображениями интерфейса, приборами и рабочей картой курса.
- Context Menu Icon Items — иконки контекстного меню. Значение Type должно соответствовать идентификатору инструмента в данных РШ АОС.

<a id="section-17"></a>
### Параметры Simulator Params Asset

Создайте Data Asset на основе CS_SimulatorParamsAsset и укажите его в Core Simulator Settings. В качестве отправной точки можно скопировать DA_CourseParams из плагина: в нём уже заполнена часть типовых параметров.

<a id="section-18"></a>
#### Params

В Params хранятся данные курса, которые не поступают из РШ АОС:

- Help Texture — изображения для окна справки тренажёра (F2).
- Measure Devises Ids — идентификаторы измерительных приборов. Доступность приборов задаётся сообщениями АОС showPlace() и updatePlace(). Название поля приведено в написании исходного проекта.
- Main Course Map — основная рабочая карта тренажёра.
- Player crouch possibility on start course — разрешение перемещения в приседе (Ctrl) при запуске курса.
- Player sprint possibility on start course — разрешение ускоренного перемещения (Shift) при запуске курса.

![Поля Simulator Params Asset](core-simulator-09-course-params.png)

<a id="section-19"></a>
#### Measure Devices Data

![Параметры измерительных приборов](core-simulator-10-measure-devices.png)

Для каждого прибора укажите его идентификатор, иконку и класс актора.

<a id="section-20"></a>
#### Hot Keys

![Параметры горячих клавиш](core-simulator-11-hot-keys.png)

Настройте действия для клавиш 1–9 и 0. Указанные клавиши автоматически появляются в интерфейсе.

- Icon — иконка горячей клавиши.
- Sub Key — часть имени метода АОС, который активирует клавишу.
- Enable — разрешение показывать клавишу в интерфейсе.

Type — тип горячей клавиши:

- Editor Step — базовый тип, используемый в большинстве тренажёров;
- Cell mode — тип для режимов с видом сверху;
- Custom — тип для отдельных тренажёров.
- Activated — тег активации.
- Used — набор тегов использования.

Для дополнительной логики создавайте дочерние классы CS_HUD и CS_PlayerController в Blueprint или C++.

<a id="section-21"></a>
### Базовые классы Gameplay Framework

Плагин расширяет классы Gameplay Framework Unreal Engine. Для поведения конкретного тренажёра создавайте дочерние классы перечисленных ниже типов.

<a id="section-22"></a>
#### CS_GameMode

CS_GameMode задаёт классы по умолчанию и управляет обменом с АОС. В нём реализованы:

- запуск WebSocket-сервера;
- приём и обработка сообщений АОС, запуск соответствующих действий;
- определение режима курса — экзамен или самоподготовка — по наличию кнопки общего алгоритма в сообщении построения меню.

<a id="section-23"></a>
#### CS_GameState

CS_GameState хранит состояние текущего прохождения:

- время прохождения курса;
- доступ к менеджеру интерактивных объектов и управление объектами;
- признак запуска курса.

<a id="section-24"></a>
#### CS_Character

CS_Character реализует управление персонажем и взаимодействие с миром:

- перемещение, обзор и изменение масштаба камеры в 3D;
- наведение на интерактивные объекты и компоненты, взаимодействие с ними;
- активацию и применение выбранного измерительного прибора.

Класс предоставляет делегаты:

- FOnZoomChangedSignature — изменение режима масштабирования в мире или меню;
- FOnPointingComponent — наведение на интерактивный компонент;
- FOnNonInteractComponent — прекращение взаимодействия с компонентом при сохранении наведения.

<a id="section-25"></a>
#### CS_PlayerController

CS_PlayerController обрабатывает пользовательский ввод и связывает интерфейс с игровой логикой:

- обрабатывает ввод в главном меню и интерфейсе;
- создаёт и отображает горячие клавиши, обрабатывает их нажатия;
- управляет взаимодействием с объектами в 2D-режиме;
- управляет интерфейсом через CS_HUD;
- открывает меню тренажёра после загрузки карты;
- отправляет сообщения АОС через WebSocket;
- обрабатывает события АОС, связанные с персонажем;
- воспроизводит звуки.

Класс предоставляет делегаты:

- FClientBattleDataInitialized — данные тренажёра из АОС инициализированы;
- FLearningStickerShow — показ обучающей подсказки;
- FOnInteractableActorUpdated — смена объекта взаимодействия;
- FOnStartedCourse — запуск курса;
- FOnTeleport — телепортация персонажа.

<a id="section-26"></a>
#### CS_PlayerState

CS_PlayerState хранит данные о состоянии игрока:

- текущую локацию;
- текущий тип взаимодействия.

Класс предоставляет делегаты:

- FOnNewLocation — смена локации;
- FOnChangeInteractMode — смена типа взаимодействия.

<a id="section-27"></a>
#### CS_HUD

CS_HUD управляет отображением двумерного интерфейса. Экземпляр HUD связан с Player Controller и выполняет следующие задачи:

- управляет элементами интерфейса;
- управляет масштабированием изображений;
- хранит геймплейные теги, которые в описываемой версии применяются в интерфейсе;
- включает и отключает ввод для CS_Character;
- передаёт в CS_PlayerController запрос на выход из тренажёра;
- отключает игровые звуки.

<a id="section-28"></a>
### Интерактивные объекты и локации

Базовый класс интерактивных объектов — CS_Interactable_Actor. Он реализует ICS_Interact_Interface и поддерживает:

- взаимодействие по ключам действий и командам АОС (ActionObjectKeys и MapMethodsCommandES);
- включение и отключение взаимодействия;
- подсветку объекта;
- телепортацию игрока к объекту;
- масштабирование при работе с 2D-объектом;
- выход из режима взаимодействия с 2D-объектом.

<a id="section-29"></a>
#### CS_Interactable_2d_Actor

CS_Interactable_2d_Actor наследуется от CS_Interactable_Actor и позволяет взаимодействовать с объектом мышью в режиме, похожем на работу с интерфейсом. Такой режим часто используется при измерениях. Дополнительно класс управляет камерой объекта:

- переключает вид на камеру объекта и показывает курсор;
- перемещает камеру в двумерной плоскости;
- при необходимости ограничивает перемещение по отдельным осям;
- настраивает скорость перемещения;
- изменяет масштаб.

<a id="section-30"></a>
#### CS_Interactable_3dPoint_Actor

CS_Interactable_3dPoint_Actor представляет точку в пространстве. При взаимодействии показывает курсор и вызывает соответствующие элементы интерфейса через АОС. Наследуется от CS_Interactable_Actor и переопределяет логику взаимодействия. Факт использования класса в текущих тренажёрах требует проверки.

<a id="section-31"></a>
#### Локации и перемещение

Стартовая локация поступает от АОС через Teleport(). При перемещении по сцене зоны перехода сообщают АОС, в какую локацию вошёл игрок.

<a id="section-32"></a>
##### Зоны перехода

CS_TransferZone_Actor наследуется от CS_Interactable_Actor. При выходе игрока из области коллизии он сравнивает расстояния до компонентов со стрелками, определяет ближайшую стрелку и отправляет АОС соответствующую локацию.

CS_TransferZoneWithWarning_Actor расширяет зону перехода: может блокировать переход и через Player Controller показывать предупреждение, полученное от АОС.

CS_TriggerZone обозначает границу рабочей зоны тренажёра и через Player Controller вызывает предупреждение в интерфейсе.

<a id="section-33"></a>
##### Телепорты

CS_Teleport_Actor наследуется от CS_Interactable_Actor и перемещает персонажа между разрозненными локациями. Целевая локация поступает от АОС через Teleport().

<a id="section-34"></a>
#### CS_Interactable_AWP_Actor

Этот класс представляет автоматизированное рабочее место (АРМ). Он наследуется от CS_Interactable_Actor; пользователь работает с виджетом экрана АРМ через камеру объекта. Класс дополнительно:

- переключает вид на камеру объекта и показывает курсор;
- инициализирует и показывает виджет экрана АРМ;
- скрывает виджет после завершения взаимодействия.

<a id="section-35"></a>
### Интерактивные компоненты

Интерактивные компоненты плагина наследуются от компонентов Unreal Engine. Общую часть их поведения задаёт интерфейс ICS_Interact_Component_Interface:

- создание и получение описания компонента;
- отключение коллизии и обводки компонента;
- получение идентификатора компонента, соответствующего идентификатору в АОС;
- проверка доступности взаимодействия;
- определение типа взаимодействия: действие, переход локации или измерение;
- настройка данных об использовании прибора;
- включение обводки и подсветки при наведении;
- обработка левого и правого нажатия на компонент.

Помимо интерфейсных методов, компоненты хранят:

- идентификатор объекта в АОС;
- описание объекта;
- ссылку на актора-владельца;
- признак доступности компонента;
- признак использования прибора;
- признак инициализации описания.

<a id="section-36"></a>
#### Static Mesh

Компонент статического меша использует CustomStencil для обводки.

<a id="section-37"></a>
#### Skeletal Mesh

Для компонента скелетного меша дополнительное поведение в исходном описании не указано.

<a id="section-38"></a>
#### Measure Point

Точка измерения наследуется от StaticMeshComponent. Она показывает место измерения с помощью материалов и хранит точку подключения щупа измерительного прибора.

<a id="section-39"></a>
#### Cells Decals

Компонент клетки наследуется от DecalComponent. Подробности его взаимодействия требуют описания.

<a id="section-40"></a>
## Локализация

Файлы локализации находятся в Content/Locales в формате JSON. CS_GameInstance инициализирует менеджер локализации. Настройка локализованного TextBlock и вспомогательных функций в исходном документе не раскрыта.

<a id="section-41"></a>
## Вопросы для уточнения и предложения

Следующие пункты — предложения и незавершённые разделы документации; они не описывают подтверждённое поведение плагина.

- Уточнить назначение HideDescription() в CS_Character и необходимость проверки изменения масштаба в Tick.
- Оценить перенос методов обмена с АОС в отдельный Utility UClass и привести связанные имена к единому стилю.
- Вынести стандартную скорость camera lag в настраиваемый параметр.
- Оценить выделение общей логики 2D-взаимодействия из CS_Interactable_Actor, отдельного интерфейса масштабирования и логики телепортации к объекту.
- Уточнить устройство локализованного TextBlock и обоснование его наследования от TextBlock.
- Дополнить инструкцию правилами упаковки папок контента при сборке проекта.
- Описать типы диалогов в CS_GameMode, менеджер голосовых сообщений в Blueprint и интерактивный актор для клеток.
- Проверить назначение пункта «САБКЛЮЧИ» в исходном черновике и использование CS_Interactable_3dPoint_Actor.
